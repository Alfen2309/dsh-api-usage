v0.3.0 聚焦「DeepSeek 今日消耗」记账的准确性与可审计性。

## 变更

- **账本 v2（token 分桶）**：今日消耗不再在调用时直接写入金额，而是按天分别累计高峰 / 空闲两档的 token（缓存命中、缓存未命中、缓存写入、输出）与调用次数；金额在读取时用内置官方价目表计算——官方调价后新数据自动按新价重算，也便于逐项审计。旧账本（v1）在启动时自动迁移，**迁移前已计价的历史金额原样保留**。
- **网页搜索按次计费**：DSH 的网页搜索走 DeepSeek Messages 的 `web_search` 服务端工具，不经过 `llm/stream`。插件现在监听 `web/deepseek-search-llm-request` 会话事件，按 **5 元 / 1000 次** 计入对应渠道（账号渠道或 API key 渠道），卡片上显示「搜索 N 次」。该请求自身的模型 token 无法从 harness 观测，仍不计入。
- **账本保留期**：新增配置 `retainDays`（默认 400 天），加载与落盘时自动裁剪更早的日期。
- **更快落盘**：账本落盘防抖从 2 秒降到 500 毫秒，进程异常退出时最多丢失 0.5 秒的计量。

## 说明

- 本次为计量增强，口径不变：仍是「DSH 自身调用」的本地估算，不包含其它客户端/web 端/APP 的消耗。
- 升级后需**重启 DSH** 生效；首次启动会自动把 v1 账本迁移为 v2。
- 账本路径不变：`$DSH_HOME/storages/api-usage/ledger.json`。
- 其它功能与 v0.2.0 一致，无破坏性接口变更（新增 `searchCalls` 字段，旧前端可忽略）。
